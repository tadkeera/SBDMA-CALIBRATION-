# خطة تنفيذ — الإصدار 2.3.0 (Master Promptt)

نطاق العمل المأخوذ من الملف المرفق، مع القرارات الهندسية التي اتُّخذت قبل البدء.

## 1. اختبار معدل التدفق (T02) — صفحة مخصصة وشبكة 10 قراءات
- **إعادة تعريف T02 في البروتوكول** كإصدار جديد `2.1.0` بدل تعديل 2.0.0 في مكانه:
  تعديل مخطط قياس داخل نسخة بروتوكول معتمدة يجعل التشغيلات التاريخية تُقرأ بمخطط جديد.
  الإصدار 2.0.0 يبقى محفوظاً (يصبح `SUPERSEDED`)، والتشغيلات القديمة تظل مرتبطة به.
- الحقول: `flow_p1000` / `flow_p1500` / `flow_p2000` — سلاسل بطول **10**، وحدة mL/min.
- المعادلات لكل نقطة ضبط: `mean` · `sd` · `rsd` · `accuracy = pct_error(mean, target)`؛
  ثم `max_abs_error` و`max_rsd` كأقصى عبر النقاط الثلاث.
- الحدود (تحت `AUTHORITY_LIMIT`): الدقة ±2.0 % (98.0–102.0 %) و%RSD ≤ 1.0 %،
  مع بقاء حدود المصادر الأخرى (المصنّع ±1.0 %، iOQ ±2.5 %) قابلة للاختيار كسياسة تشغيل.
- صفحة `/lab/flow-rate`: 30 حقلاً (3 × 10، `step="any"`)، لوحة الحدود المرجعية العلوية/السفلية
  في mL/min، ولوحة حساب حيّة (المتوسط، SD، %RSD، %الدقة، الحالة) لكل نقطة + الحالة الإجمالية،
  تلوين أخضر/أحمر، ثم **Run Calibration** (رسم المخططات) ثم **Save** (AJAX) ثم شهادة PDF.
- **إعادة الحساب على الخادم**: مسار `POST /api/v1/flow-rate/calculate` يعيد الحساب بمحرّك
  الخادم (Decimal) ويعيد الحالة والحدود المطبقة — العميل معاينة فقط، والحكم للمخدم.

## 2. دورة الاعتماد في الشهادة
- قسم جديد في الشهادة: **حالة الاعتماد** — مراجعة المشرف (`Approved` / `Pending Review`)
  واعتماد ضمان الجودة (`Approved` / `Pending QA Approval`) مع الاسم والوقت وخط توقيع.
- الشهادة الرسمية تبقى مقفلة على التشغيل المعتمد والمقفل (كما هي).
- إضافة **نسخة أولية (PROVISIONAL)** بعلامة مائية «مسودة — غير صالحة كشهادة» تعرض حالات
  الانتظار، كي يرى المستخدم موضعه في الدورة قبل الاعتماد، دون أن يتحول المستند إلى شهادة.

## 3. الأدوار والصلاحيات
- إعادة تسمية `TECHNICAL_REVIEWER` → `SUPERVISOR` بترحيل آمن (نقل الصلاحيات وربط
  المستخدمين ثم حذف الصف القديم داخل معاملة واحدة؛ لا يُفقد أي إسناد).
- شاشة المستخدمين: **مربّعات اختيار** لكل دور في الإنشاء والتعديل (الخادم يدعم الأدوار
  المتعددة أصلاً عبر `user_roles`، مع منع تصعيد الصلاحيات وفصل المهام).
- التحقق من إسناد المهام الثلاثي على الخادم: محلل ينفّذ، مشرف يراجع، ضمان جودة يعتمد —
  عبر الصلاحيات `calibration.run` / `.review` / `.approve` + فصل المهام.

## 4. خط Cairo العربي
