## الأدوار الافتراضية

| الدور | الرمز | النطاق |
|---|---|---|
| مدير النظام الأعلى | `SUPER_ADMIN` | كامل — محمي من الحذف/التعطيل |
| مسؤول النظام | `SYSTEM_ADMIN` | الإدارة المركزية والأجهزة والمستخدمين |
| محلل مختبر | `ANALYST` | قسمه فقط — إدخال القراءات وتشغيل المعايرة |
| مراجع فني | `SUPERVISOR` | قسمه — تشغيل + مراجعة فنية |
| معتمد ضمان الجودة | `QA_APPROVER` | إشراف شامل — اعتماد الحدود والنتائج |
| هندسة وصيانة | `ENGINEERING_SERVICE` | تذاكر وأعطال — بلا صلاحية حسابية |
| مستخدم استعراض | `VIEWER` | قراءة فقط |

## قواعد غير قابلة للتجاوز

1. **Deny-by-Default:** كل نقطة API تتحقق من الصلاحية ونطاق القسم على الخادم. إخفاء زر
   في الواجهة ليس وسيلة حماية.
2. **فصل المهام (21 CFR Part 11):** `analyst_id ≠ reviewer_id ≠ qa_approver_id` لنفس التشغيل.
   مُنفَّذ في الواجهة (`/qa`) ويُفرَض في الخادم كقيد قاعدة بيانات.
3. **لا تصعيد صلاحيات:** لا يجوز لأي مستخدم منح صلاحية لا يملكها.
4. **حماية `SUPER_ADMIN`:** لا يمكن حذفه أو تعطيله أو تغيير دوره إلا من مثيل `SUPER_ADMIN` آخر.
5. **عزل الأقسام (IDOR):** كل استعلام مقيّد بـ `department_id` في `WHERE`، وأي محاولة وصول
   عبر تعديل معرّف تُرجع `404` (لا `403`) لمنع تسريب الوجود.
6. **إلغاء الجلسات:** تغيير كلمة المرور أو تعطيل الحساب يُلغي كل refresh tokens فوراً.
7. **تعدد الأدوار:** المستخدم قد يحمل أكثر من دور في الوقت نفسه (محلل ومشرف قسم، مثلاً)؛
   الصلاحيات تُجمَع من كل أدواره، والتحقق في الخادم على مستوى الطلب لا على مستوى الواجهة.
   نموذج الإدارة يعرض الأدوار **خانات اختيار** (Checkboxes) لا أزرار اختيار واحد، والدور الذي
   يرفضه الخادم (أعلى من رتبتك، أو دور اعتماد لمن يدير الحسابات) يظهر معطّلاً لا مخفياً.
8. **ثلاث طبقات فرض:** (1) الواجهة تُخفي ما لا يُسمح، (2) نقطة النهاية تتحقق من الصلاحية
   ونطاق القسم وتعيد `403 PERMISSION_DENIED` أو `404`، (3) قاعدة البيانات تحمل القيود
   (تفرّد التوقيع، منع الاعتماد الذاتي، سلسلة التدقيق). تعطيل أي طبقة لا يُعطّل الحماية.
