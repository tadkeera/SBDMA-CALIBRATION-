### قاعدة الاختبار حقيقية لا وهمية
- خادم PostgreSQL 17.12 فعلي بقاعدة `sbdma_test`.
- المخطط يُبنى **بأوامر Alembic الفعلية** (`alembic upgrade head`) لا بـ`create_all`،
  لذلك تُختبر الـ Triggers نفسها لا نسخة مبسّطة منها.
- البيانات الأولية تُبذر من نفس `app.seed` المستخدم في الإنتاج.
- الطلبات تمرّ عبر `httpx.ASGITransport` على تطبيق FastAPI الحقيقي (Middleware، CORS، حدود الطلبات، معالجات الأخطاء).

### تطابق المحركين (أهم اختبار في المشروع)
`tests/parity/run_ts_engine.ts` يُحزَّم بـ`esbuild` ويُشغَّل تحت Node على نفس ملف القراءات
الذي يستهلكه محرك Python. تُقارَن 3 سياسات حدود (`AUTHORITY_LIMIT`, `SOP_LIMIT`,
`MANUFACTURER_SPEC`) على مستوى **كل اختبار وكل تقييم مقياس** — لا على المستوى الإجمالي فقط.
النتيجة الحالية: **صفر انحراف** في 3×13 اختباراً ومئات التقييمات. أي انحراف يعني أن المتصفح
قد يعرض PASS بينما يخزّن الخادم FAIL، وهو أخطر عيب يمكن أن يُشحن.

### ما يُثبته `test_api_runs.py` تحديداً
1. **RBAC:** مطالع (`VIEWER`) لا يستطيع إنشاء تشغيل ⇒ 403 `PERMISSION_DENIED`.
2. **Idempotency:** إنشاء تشغيل بلا `Idempotency-Key` ⇒ 422.
3. **IDOR:** محلل قسم الكيمياء لا يرى جهاز قسم الفيزياء ويحصل على 404 لا 403 (لا تسريب وجود).
4. **حاجز الصلاحية:** أداة مرجعية منتهية ⇒ 422 `EXPIRY_GUARD`.
5. **المسار الناجح:** 13/13 PASS ⇒ مراجعة موقّعة ⇒ اعتماد ⇒ `is_locked=true` وبصمة شهادة
   بطول 64 حرفاً ⇒ تحديث دورة الجهاز (+180 يوماً بالضبط).
6. **القفل:** إعادة تنفيذ تشغيل مقفل ⇒ 409 `RESULT_LOCKED`.
7. **فصل المهام:** المحلل لا يملك صلاحية المراجعة، والقاعدة ترفض أن يكون المراجع = معتمد الجودة.
8. **الاعتماد قبل المراجعة** ⇒ 409، و**مراجعة تشغيل غير مكتمل** ⇒ 409.
9. **لا PASS صامت:** بيانات ناقصة ⇒ `INCOMPLETE`؛ انحراف 1.2 mAU/h ⇒ `T11 FAIL` والتشغيل `FAIL`.
10. **حدود SOP المعيبة:** نفس القراءات المطابقة تحت `SOP_LIMIT` ⇒ `UNDER_REVIEW`، والاعتماد محظور 422 `LIMIT_CONFLICT`.
11. **ما بعد الأعطال:** مكوّن `D2_LAMP` يقيّد التنفيذ على T01/T09/T11 فقط.
12. **سلامة التدقيق:** `verify_chain` سليم؛ `UPDATE`/`DELETE`/`TRUNCATE` على `audit_logs` مرفوضة بقاعدة البيانات.
13. **قفل النتائج:** بعد الاعتماد، تعديل أو حذف أي نتيجة مقفلة بـ SQL مباشر مرفوض (13/13 نتيجة مقفلة).
14. **قفل التشغيل:** إعادة فتحه أو تغيير `certificate_hash`/`overall_status`/`qa_approver_id` أو حذفه مرفوض.
15. **KPIs والبروتوكول:** `/kpis` من صفوف حقيقية، و`/protocols/...` يعيد 13 اختباراً و108 حد.
16. **الصيانة:** تذكرة على `DETECTOR` تستنتج T09/T10/T11/T12، والإنجاز يعيد الجهاز `ACTIVE`.

### حزمة E2E — `npm run e2e`

> **استبدلت `e2e_live.py`.** السكربت القديم كان جولة يدوية تحتاج متغيّرات بيئة خارجية
> وملف مدخلات في `/tmp` واتصالاً مباشراً بقاعدة البيانات لاشتقاق رمز TOTP — أي أنه لا
> يعمل في CI، وما لا يعمل في CI لا يُعتبر تحققاً. الحزمة الجديدة داخل المستودع، تشغّل
> نفسها بنفسها، وتفشل بوضوح إذا غاب أي شرط.

```bash
npm run e2e:prepare     # قاعدة بيانات معزولة: إنشاء + ترحيل + بذر بكلمات مرور الاختبار
npx playwright install chromium   # مرة واحدة
npm run e2e             # يرفع uvicorn :8000 و next start :3000 بنفسه ثم يوقفهما
```

ماذا تفعل الحزمة:

| البند | التفصيل |
|---|---|
| الخوادم | `playwright.config.ts` يرفع FastAPI على `:8000` ونسخة **الإنتاج** من Next على `:3000` (لا `next dev`)، ويوقفهما بعد الانتهاء |
| قاعدة البيانات | `sbdma_e2e` منفصلة تماماً، تُبنى في `e2e/prepare-db.sh`؛ الاختبار يرفض أن يعمل على أي قاعدة أخرى |
| الحسابات | `e2e/fixtures/accounts.json` مصدر واحد يقرأه كلٌّ من البذرة والمتصفح (و`backend/tests/test_e2e_fixtures.py` يمنع انحرافها عن `SEED_USERS`) |
| العامل الثاني | التشغيل التمهيدي يسجّل TOTP للمراجع ومسؤول الجودة ثم يدخل بهما **عبر شاشة الدخول** ويحفظ الجلسة (`storageState`)؛ رمز TOTP أحادي الاستخدام والخادم يمنع إعادة استخدامه، فالدخول مرة واحدة لكل دور هو ما يجعل الحزمة حتمية |
| البيانات | `e2e/fixtures/compliant_inputs.json` = **نفس** مجموعة `COMPLIANT_INPUTS` في `backend/tests/test_api_runs.py` (13 اختباراً، 61 حقلاً)، ويُتحقق من التطابق في pytest |
| وحدة التحكم | أي خطأ JavaScript يُفشل الاختبار (`e2e/lib/fixtures.ts`)، باستثناء 401/403/favicon المشروعة |
